# Verification boundaries and open work

This document records observed limits rather than promising unsupported behavior. Each item links to its evidence where one exists.

## The official sample

- **Outcome:** the unchanged image [completed](../artifacts/official-sample-live/report.html) in a brand-new workspace on the recorded build, with one fresh Gemini reading, local OCR and no operator review. See its [acceptance checks](../artifacts/official-sample-live/verification.json). Later recovery and review fixes have automated regression coverage, with no new Fakturama run.
- **Email:** Fakturama 2.2.0 did not store `marta.klein@example.test`. A new Debtor keeps a blank email. This was observed by [reopening the saved contact](../artifacts/official-sample-live/saved-contact.png), and the receipt records it. An earlier engineering note attributed this to Apache Commons `EmailValidator` in `ContactEditor`, but no artifact in this repository demonstrates that cause. The observed behavior is the claim.
- **Release run with reused readings:** an [earlier run](../artifacts/official-sample-release/report.html) reached the same result, but both of its Gemini responses came from the cache, so it made no provider call. Its `mode` field says "live vision", which overstates it, and its repair reading is not marked as cached. That prompted the [source change](../artifacts/source-change-after-r1.diff) and the final run.
- **Run before the scale fixes:** [this run](../artifacts/official-sample-final/report.html) reused a real cached first reading. It matched OCR on every value but omitted one evidence path, so the repair pass made one fresh call. See the [extraction note](../artifacts/official-sample-final/extraction-note.json).
- **Rehearsal:** the [first attempt in an empty workspace](../artifacts/official-sample-fresh-rehearsal/report.html) stopped once because a new database has no Orders node in its Documents tree. That was fixed and the run was repeated in another new workspace, so the rehearsal counts one operator review.
- **Second official record:** [PO000011 / INV000011](../artifacts/official-sample/report.html) in the older `integration` workspace used a manual transcription, not a live call, and an earlier build. Its seven recorded resolutions changed no source value: six fixed technical stops and one recorded the approved email policy. Its existing Debtor, CUST000001 in `integration`, holds a `.com` email, changed through the UI by an earlier compatibility test and never changed by that run. The last automatic stop in the job's history was a payment-combo ambiguity, not an email failure. Its screenshot `saved-contact.png` captured the delivery tab, so its [later audit](../artifacts/official-sample/later-audit/saved-contact.png) is the evidence for that field.

## Desktop coverage

- **Source identity:** each receipt records a hash of the package source. The final official run used `51644607`, and the `R1` and `R1X` scenarios and the `R1` benchmark used `99e0c8a2`. The final source [differs](../artifacts/source-change-after-r1.json) in extraction/provider metadata, report wording, storage, CLI/platform guards, service review, workflow recovery and saved-state validation. The Fakturama driver is unchanged; workflow and validation now reject additional unsafe recovery states. Four reports were regenerated after the earlier wording fix, and their journals, receipts and checks are unchanged. The `F1`, `F1X` and `F2` series ran before the scale fixes. Older folders such as `desktop-clean` and `desktop-recovery` predate later adapter changes and carry no hash. All are kept as history, and their reports keep an older banner that counts provider retries as operator review.
- **Fixes after the recorded runs:** independent review found two defects after the desktop runs were recorded. `itc.cmd resume` after a provider failure stopped at `VALIDATED`, and a key first seen on a duplicate image was not bound to that image. Both are fixed and covered by automated tests using the simulator and temporary databases. `itc.cmd resume` after a provider failure has not been run against Fakturama: the acceptance scripts call the service directly, and the API resumes through the worker.
- **Follow-up recovery review:** generated Order and Invoice identifiers are now checked during resume, including surviving drafts; untracked saved Invoices and unknown unpaid states stop for review. A corrected duplicate can reuse the original verified receipt without desktop work. Reference corrections release this job's old reservation before desktop execution; after an Order creation intent, the reference cannot change. These fixes are covered by simulator and database regressions, not another real-desktop run. An interrupted New Order action with no observed generated identifier requires reconciliation rather than automatic adoption.
- **CI portability:** the initial GitHub Actions run failed Linux type checking because Windows-only APIs used platform guards the type checker did not recognize. These guards now use `sys.platform`; both platform targets are checked. This does not add Linux desktop support or another real-desktop acceptance run.
- **Explicit input:** the `R1X` recovery after Order Save, unpaid and new-masters scenarios had no model call, because Gemini was unavailable when they ran. They test the desktop, not extraction.
- **Benchmark:** [7 of the 27 planned runs](../artifacts/desktop-benchmark/R1/results.json), one per case. Repeats and 30 lines with new or mixed masters were not measured.
- **Display:** only 1920x1200 at 125% has recorded acceptance. Table reading depends on current header pixels, clipboard exports, dialog resizing and a nine-column Items profile, and selector icons use image matching. Other scales and window sizes are untested.
- **Process and session loss:** recovery scenarios stop the orchestrator after a real UI action returns. They do not kill Fakturama, lock the session or lose power.
- **Masters and data:** duplicate and conflicting masters are covered by automated tests, not by real-desktop acceptance. Address specification and district are absent from the extraction contract and desktop mapping; orders requiring them need manual handling. There is no dedicated guard to detect those supplied fields. Non-zero shipping needs a verified shipping definition and stops for review. Rounding was checked in [five draft probes](../artifacts/rounding/results.json), plus the saved mixed-VAT discount case. That does not establish every combination.
- **Sub-cent lines:** a [30-line draft](../artifacts/rounding/cumulative-line-finding.json) stopped before Save because Fakturama's total differed from the source's by a cent. Its total matches summing unrounded lines and rounding once, which is inferred from that document and one 10-line document. Such documents stop for review and are not a supported case, and the 30-line benchmark uses whole-cent lines.
- **Abandoning a draft:** `abandon` discarded three real unsaved drafts that had stopped before Save. Each was identified and checked against saved documents first. Any job with a Save or follow-up intent must be resumed instead.
- **Application side effects:** the adapter changes four Fakturama Preferences, listed in the README. They persist in the workspace.
- **Setup:** the documented setup has run only on the development machine. Independent review found a setup step that used the base Python instead of the project environment, which runs on this machine had not exposed, so a clean machine may reveal more.
- **Office export:** LibreOffice and OpenOffice export are not installed or verified here.
- **Scale:** throughput measurements come from one warm application on one desktop. Multi-host ownership and PostgreSQL are extension points, not measured features.

## Extraction

- **Sample size:** [12 development and 12 held-out synthetic documents](../artifacts/accuracy-and-usage.json) matched exactly, with no incorrect acceptance. That set is small, generated and still needs human review of its ground truth. Real scanned or photographed orders have not been evaluated.
- **False reviews:** [two of four harmless image changes](../artifacts/robustness/results.json) stopped for review despite correct vision readings, and a [discount above the item table](../artifacts/desktop-fresh-extraction-review/report.html) stopped because the parser's table boundary preceded the rows. OCR also joined telephone spaces there. These are safe failures but extra manual work.
- **Language:** tested layouts use English labels. German-labelled layouts are not supported by the field parser.
- **Providers:** only Gemini 3.5 Flash-Lite has made live calls. The OpenAI adapter is untested. No billing export was collected.

## Provider availability

Gemini returned HTTP 503 on [174 of 183 recorded requests](../artifacts/provider-availability.json) during acceptance on 5 November. Calls with the same key and model succeeded between failures, so this was service availability, not configuration. Extraction stopped and was retried 51 times; 8 jobs recovered and 4 stayed stopped. A stopped job makes no desktop change.

The final official run waited about 14 minutes through five stops. Three release scenarios used explicit input rather than waiting longer, and are labelled. The worker does not back off automatically: each retry goes through review and resume, by a person or an acceptance script.
