# Candidate code walkthrough

Be able to explain these paths directly from the code, including their failure cases.

1. **Literal extraction:** `models.py`, `ocr.py`, `extraction.py`. Show how the image is read independently, why OCR text is withheld from the first vision request, and why two agreeing readings still do not guarantee correctness. Explain one repair pass, evidence provenance, cache invalidation, schema validation, and rate-limit handling. The final official run needed no repair; the [previous one](../artifacts/official-sample-final/extraction-note.json) shows the repair pass firing on a missing evidence path, not a value difference.
2. **Acceptance and money:** `validation.py`. Walk through both sample rows, the 10% chair discount, €570.00 net, €108.30 VAT, and €678.30 gross. Explain `Decimal`, line/group rounding, fractional quantities, repeated SKUs, and undiscounted master gross versus transaction net. Show the five measured desktop probes. Explain why document discount is displayed negatively and why the displayed item subtotal differs from final net; both remain in the saved observations.
3. **The email exception:** `validation.py`, `workflow.py`. Show how narrow `email_exception_applies` is, how `verify_document` and `_verify_customer` exempt only that field, and how `_source_value_warnings` records the value read from a reopened contact. Show `ITC_EMAIL_POLICY=strict`, and the tests proving that every other difference still stops.
4. **Business sequence:** `workflow.py`. Trace Order-first execution, exact selector matching, missing-master branches, payment mappings, line verification, saved Order verification, the Data > Documents row comparison, follow-up Invoice, source payment date, and final persistence checks.
5. **Windows boundary:** `windows.py`, `ui.py`. Explain scoped locators, one initialized COM worker thread, current-image icon matching, SWT event delivery, NatTable clipboard validation, why selected-row copies reuse established headers, and why an unknown control stops for review.
6. **Recovery:** `store.py`, `workflow.py`. Pick an interruption immediately after Save. Explain what intent proves, what it cannot prove, how saved records are reconciled, how duplicate creation is avoided, and why an expired lease cannot authorize a second desktop writer. Explain when `abandon` is allowed and why any Save intent refuses it.
7. **Interfaces and evidence:** `service.py`, `api.py`, `reporting.py`. Demonstrate image/key deduplication, conflicting external references, review audit, asynchronous job submission, and the source/observed-value report. Distinguish a real desktop receipt from simulation/reviewed replay, and show the source hash in a receipt.

The abstractions exist because extraction, financial acceptance, durable ownership, and Windows interaction have different failure modes. Avoid introducing more services until measured queue pressure or operational constraints justify them.
